## authoritative protocol references and useful upstream components

- **REUSE / ADAPT (Unlicense):** official Swift `localPackages/BitFoundation/Sources/BitFoundation/{BinaryProtocol,BitchatPacket,MessageType,PacketPayloadLimits,FileTransferLimits}.swift` and `bitchat/Protocols/BitchatFilePacket.swift` for canonical v1/v2, padded signature input, compressed zlib payloads, `0x22` TLVs and limits. Port with independent cross-language vectors; chatt3r already ported the signed short-text subset; don't rewrite that working path for style.
- **ADAPT / REFERENCE ONLY:** official `Services/BLE/{BLEOutboundFragmentPlanner,BLEFragmentAssemblyBuffer,BLEFragmentHandler,BLEFileTransferHandler,BLEIncomingFileStore}.swift` for per-type bounded reassembly, fragment recovery, signature-before-save, quota and safe storage. iOS APIs/storage/queues must not leak into portable Rust. The existing public-file recovery is gossip sync, not a guaranteed ACK for every file.
- **REFERENCE ONLY (GPL):** Android `mesh/{MeshCore,FragmentManager,FragmentingPacketSender,UnifiedMeshService,BluetoothMeshService}.kt`, `wifi-aware/WifiAwareMeshService.kt`, `service/TransportBridgeService.kt` for shared mesh core and cross-transport dedup. No Kotlin copy. Android already provides independent BLE and Wi-Fi Aware meshes, local transport preference and bridging; a simple dual-transport router is **not novel**.
- **ALREADY HAVE BETTER:** chatt3r's actual BitChat-compatible short signed text, fresh-scan guard, Windows one-central server, direct-ATT paired-iPhone workaround and scoped no-replay startup retries; none of the other desktop checkouts show this specific proven Linux↔Windows host path. This is interoperability engineering, not a new protocol.

## opportunity / distinctness test

A high-level `BLE + fast direct + transfer` diagram duplicates Android's `UnifiedMeshService`/`TransportBridgeService` for transport selection and relay, and Apple's existing wire/media design for small files. A *potential* chatt3r contribution is reproducibly tested desktop-first **Linux + Windows + stock iPhone** interop, safe generic-file receive/send within stock format, explicit cross-transport delivery identity and resumable/integrity-verified *large* arbitrary files on infrastructure-free heterogeneous hardware. None of those broader claims are implemented or proven today. Stable peer identity and session migration require design and a partner client; a new protocol must not replace `0x22` for basic compatible files.
